An Introduction to JavaScript

What JavaScript actually is, where it executes, and what it can (and can't) do in a real browser.

JS
Modern JavaScript Tutorial Practical, code-first breakdown for developers

Let's start without any motivational fluff: what is JavaScript, really?

Think of the web as three basic layers:

  • HTML gives the page its structure (headings, buttons, inputs).
  • CSS handles how it looks (typography, colors, layouts).
  • JavaScript makes it do stuff.

Every time you click a button and a dropdown opens, or you like a post and the counter updates instantly without the whole page reloading — that's JavaScript running inside your browser.

Quick Reality Check: Java vs JavaScript

People often ask if JavaScript is related to Java. It isn't. Brendan Eich created JavaScript in 10 days at Netscape back in 1995. At that time, Java was the hot enterprise language, so Netscape renamed it from “LiveScript” to “JavaScript” purely for marketing buzz.

As the classic developer saying goes: Java is to JavaScript as car is to carpet. They are completely different languages with entirely different design goals.

How the web layers fit together: HTML gives structure, CSS styles it, and JavaScript makes it interactive.

Where Does JavaScript Actually Run?

For a computer to run JavaScript, it needs a program called a JavaScript engine.

You don't need to know compiler theory to write great code, but here is what matters right now:

  • V8 is the engine inside Google Chrome, Brave, Edge, and Node.js.
  • SpiderMonkey is the engine inside Mozilla Firefox.
  • JavaScriptCore (Nitro) is the engine inside Apple Safari.

The JavaScript engine only executes JavaScript syntax (variables, loops, functions, objects). Everything else comes from the environment it runs in.

If you run JavaScript in a browser, the browser gives JS access to things like the web page (document), user clicks, and network requests (fetch).

If you run that exact same JavaScript in Node.js, there is no browser window or HTML button. Instead, Node.js gives JS access to your computer's files, operating system, and backend databases.

The core engine runs JavaScript syntax everywhere. The host environment determines whether you can manipulate buttons or access server files.

What Can In-Browser JavaScript Actually Do?

When JavaScript runs inside a web page, it can:

1. Update the UI Dynamically
DOM Manipulation

Add new HTML elements, delete existing ones, change text, swap styles, and trigger smooth CSS animations on the fly.

2. Respond to User Actions
Event Handling

Listen for clicks, keyboard typing, form inputs, window resizing, and mouse movements to make the interface feel alive.

3. Talk to Servers in the Background
Network Requests (Fetch API)

Send and receive data from an API (e.g. submitting a payment, searching products) without reloading or freezing the page.

4. Remember User State
Client Storage

Save small pieces of data directly in the browser — like keeping a user's dark mode preference in localStorage or saving a session cookie.

The Browser Sandbox: What JS Cannot Do

Imagine if visiting a random website allowed that site to read your laptop's personal folders, delete your documents, or secretly turn on your camera. The web would be unusable.

To prevent this, in-browser JavaScript runs inside a strict Security Sandbox:

  • No arbitrary filesystem access: JavaScript on a webpage cannot read, write, or delete files on your hard drive. (It can only receive a file if you explicitly drag-and-drop it or select it using an upload input).
  • No silent hardware access: Web pages cannot access your microphone, camera, or GPS location without you explicitly clicking "Allow" on a browser permission prompt.
  • Same-Origin Policy: Code running on my-cool-game.com cannot look inside an open tab running your-bank.com. Tabs from different domains are strictly isolated from each other.

Who Decides What's in JavaScript?

Who decides that modern JavaScript should have arrow functions (=>) or optional chaining (?.)?

The language is governed by an official standard called ECMAScript (specification ECMA-262). When Chrome, Safari, or Firefox build their JavaScript engines, they follow this exact specification so your code behaves the same way everywhere.

  • TC39 (Technical Committee 39): The group of browser vendors, engineers, and academics who review proposed new language features through 5 formal stages (Stage 0 Proposal to Stage 4 Shipped).
  • MDN Web Docs (developer.mozilla.org): The official specification is written like a dry legal document. MDN is the actual manual every real working developer uses daily for syntax, practical examples, and edge cases.
  • Can I Use (caniuse.com): A quick lookup tool to check whether a specific browser version supports a newly released feature.

Your Immediate Playground: The Developer Console

Here is the best part about JavaScript: you don't even need to configure a build tool or open an editor to test an idea. You can run code right now in your browser.

Press F12 (or Cmd + Option + I on Mac) right now, and click on the Console tab.

Quick Dev Tip

In the browser console, pressing Enter runs the code immediately. If you want to write a multi-line function without executing it right away, press Shift + Enter to insert a new line.

Quick Recap: 5 Things to Remember

  1. JavaScript isn't Java: Created in 10 days in 1995; named after Java purely for early marketing buzz.
  2. Engines execute syntax, hosts provide APIs: V8 runs your code; the browser provides UI APIs (DOM, Fetch) while Node.js provides server APIs (filesystem, network sockets).
  3. Web pages are sandboxed: In-browser JS cannot touch your local hard drive or steal data across different tabs.
  4. ECMAScript sets the rules, MDN documents them: Use MDN Web Docs as your primary reference when looking up any method or syntax.
  5. You already have an IDE: Press F12 in any browser to open DevTools Console and run experiments instantly.
