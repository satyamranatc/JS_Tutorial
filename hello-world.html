5. Hello, world!

How HTML runs your JavaScript code, the <script> tag, inline vs external files, and the 3 distinct ways to print output.

JS
Modern JavaScript Tutorial Practical, code-first breakdown for developers

Ever wondered why every single programming tutorial in human history starts with the words “Hello, world!”?

The tradition goes back to Brian Kernighan at Bell Labs in 1972. When you learn a new language, the first goal is never to build a complex banking system on day one. The goal is to write the smallest possible piece of code that proves the pipeline works: your editor saves the file, the browser parses it, and something visible happens on screen.

In JavaScript, that journey starts with a simple question: How do we actually attach JavaScript code to an HTML web page?

1. The <script> Tag

JavaScript programs can be inserted almost anywhere into an HTML document using the <script> tag.

Here is a complete, minimal HTML page that runs JavaScript:

index.html MINIMAL EXAMPLE
<!DOCTYPE html> <html> <body> <h2>My First Web Page</h2> <!-- JavaScript begins here --> <script> alert('Hello, world!'); </script> </body> </html>

Save this in a file named index.html and double-click to open it in Chrome, Safari, or Firefox. A small modal dialog box will pop up displaying the text: Hello, world!

Why you don't need type="text/javascript" anymore

In older tutorials or legacy code from 2005, you will often see:
<script type="text/javascript" language="javascript">

Back in the HTML4 era, browsers supported multiple scripting languages (like VBScript in Internet Explorer). But with modern HTML5, JavaScript became the default and only native language of the web. Today, writing type="text/javascript" is completely redundant — just write <script>.

2. Internal vs External Scripts

Writing JavaScript directly inside your HTML file is called an internal script. It's great for quick demos or small 5-line experiments.

However, once your application grows beyond a few lines, keeping JavaScript mixed inside HTML files becomes a mess. Professional codebases extract JavaScript into separate .js files using the src attribute:

index.html • Linking external script EXTERNAL FILE
<!-- In index.html --> <script src="script.js"></script>

And in your separate file named script.js (located in the same folder):

script.js JAVASCRIPT FILE
alert('Hello, world from an external file!');

Why External Scripts Are the Production Standard:

  • Browser Caching (Speed): If you have 20 pages on your website that all use script.js, the user's browser only downloads the file once on the first page, and caches it in memory. Subsequent page loads are instant.
  • Separation of Concerns: Your HTML stays clean and focused purely on content and markup, while your JavaScript stays organized in focused logic files.
The #1 Beginner Trap: The Ignored Script Body

A very common beginner bug happens when someone tries to combine both approaches into one tag:

<script src="script.js">
  alert('Hello!'); // THIS WILL BE COMPLETELY IGNORED!
</script>

Rule: If the src attribute is set on a <script> tag, the browser completely ignores whatever code you wrote inside the tag. If you need both, use two separate tags:
<script src="script.js"></script>
<script> alert('Now I run!'); </script>

3. The 3 Distinct Ways to Output in JavaScript

When a beginner says “I want to print Hello World in JavaScript”, they could mean three completely different things depending on context:

Method What it does When do developers use it?
alert("Hello") Opens an OS-level modal popup. Quick beginner demos. Rarely used in real production because it freezes the whole browser tab until clicked.
console.log("Hello") Prints output quietly into Developer Tools (F12). Used constantly by developers every day to inspect data, debug API responses, and check variable values without disturbing users.
document.body.innerHTML Writes text directly into the web page DOM. Updating the actual screen UI that your users see.

Let's see all three in action side-by-side:

Comparing the 3 Output Methods TRY THESE IN SCRIPT.JS
// 1. Modal Popup (Blocks user interaction until OK is clicked) alert("Hello, world from a popup!"); // 2. Developer Console (Check DevTools with F12 -> Console) console.log("Hello, world from the console!"); // 3. Web Page DOM (Writes text right onto the screen) document.body.innerHTML = "<h1>Hello, world on the page!</h1>";

4. Where Should the <script> Tag Live?

A common point of confusion for beginners is: Should I put the <script> tag in the <head> or at the bottom of <body>?

To understand the answer, look at how a browser reads an HTML document:

  1. The browser starts parsing HTML line-by-line from top to bottom.
  2. When it encounters a <script> tag, it halts HTML parsing immediately.
  3. It downloads the script file and executes the code.
  4. Only after the script has completely finished running does it resume rendering the rest of the HTML.

This behavior is known as the Parser Blocking Problem.

Gotcha
Why putting scripts in <head> without attributes breaks your UI

If your script is in <head> and tries to find a button on the page (e.g. document.getElementById('submit-btn')), it will crash with null because the browser hasn't parsed the <body> yet! The button doesn't exist when the script runs.

Script loading lifecycle: The defer attribute lets the browser download your JS file in the background without blocking the HTML parser.

The Modern Best Practice: Put your script tag in the <head>, but add the defer attribute:

index.html • Best Practice RECOMMENDED
<!-- Downloads in background without pausing the HTML parser --> <script defer src="script.js"></script>

5. Common Beginner Mistakes to Avoid

When writing your first lines of JavaScript, these are the 3 syntax errors every developer runs into at least once:

Mistake 1
Forgetting quotes around text

alert(Hello); // Crashes!
In JavaScript, text without quotes is treated as a variable name. Because no variable named Hello exists, the engine throws: Uncaught ReferenceError: Hello is not defined.
Fix: Always wrap plain text strings in quotes: alert("Hello");

Mistake 2
Mismatched quotes

alert("Hello'); // Crashes!
If you start a string with a double quote ("), you must close it with a double quote. If you mix single and double quotes, JS throws: SyntaxError: Invalid or unexpected token.

Mistake 3
Case sensitivity mistakes

Alert("Hello"); // Crashes!
Console.Log("Hello"); // Crashes!
JavaScript is strictly case-sensitive. The function is lowercase alert() and console.log(). Writing capital letters throws a TypeError.

6. Try It Yourself: Your First Mini-Exercise

Don't just read code — build muscle memory right now. Try this 2-minute task:

  1. Create a new folder on your computer named js-test.
  2. Inside it, create an index.html file with a simple heading and a linked script:
    <script defer src="app.js"></script>
  3. In the same folder, create app.js and add:
    console.log("My JS pipeline is working!");
  4. Open index.html in your browser, press F12, open the Console tab, and verify your message is printed!

Quick Recap: 5 Things to Remember

  1. The <script> tag connects HTML & JS: Modern HTML5 does not need type="text/javascript".
  2. Always use external files in real apps: <script src="script.js"> allows the browser to cache your code and keeps HTML tidy.
  3. Never put code inside an external <script src="...">: Any inline code inside a script tag with a src attribute is completely ignored.
  4. console.log() is your primary tool: alert() freezes the screen; console.log() outputs quietly to DevTools for developers.
  5. Use the defer attribute: <script defer src="..."> prevents scripts from blocking the HTML parser during page load.
